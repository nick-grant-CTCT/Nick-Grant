## 1. CTCT - Slide Template (brand vocabulary)

Use for: chrome, type, section dividers, big-stat wells, TOC, icon placement rules.

Patterns to copy:

- **Proxima Nova** titles; theme brand colours only.
- **CONFIDENTIAL** badge bottom-left (template chrome — do not redraw).
- Orange / filtered hero imagery **only on title / intro** slides; unfiltered photography on content slides.
- Layout gallery shapes: vision quote, principles grid, numbered columns, big stats (`20M` / `89%` / `54`), section openers with large `01`.
- Icons from the template libraries — recolour with fill; do not invent emoji.

## 2. Draft GEM slides (story-led exec / GEM)

Use for: V3 Unite GEM updates, value narratives, UX change sets, near-term roadmaps.

Patterns to copy:

- **Title lockup:** programme name + section number (`01`) + dated subtitle (`GEM update August 2026`).
- **Story before numbers:** emotional Now → Next bridge slide, then quantified PREVIOUSLY vs PLATFORM bars (Increase TAM / Move Faster / Sell More).
- **Pipe titles:** `Topic | framing` (e.g. `The Value of V3 | Today vs the V3 Platform`).
- **Numbered change panels:** `01 · Name` / short label / Change + Why (four UX changes).
- **Problems ↔ Strategy:** two columns of numbered items; strategy answers the problems — not a dump of bullets.
- **Roadmap swimlanes:** time across the top; parallel tracks (Demo spikes, Builds, UX, UA, OGC) with dated milestones — figure dominates.
- **Three value pillars** as closing figure (icon + short name + one sentence).
- **Talk track off-slide:** dense explanation lives in speaker notes; on-slide stays sparse.

Anti-patterns this deck avoids (keep avoiding):

- Traditional programme-update chrome when the story is a critical narrative.
- Mixing two different “speed” concepts on one bar row — split into dedicated slides.

## 3. V3 Major Program Slides Aug 26 (programme / decision)

Use for: major-programme boards, V2→V3 journey, allocation, isolation-test architecture.

Patterns to copy:

- **Owner line on title:** `Josh (Project)  Nick G (Product)  Colin (Tech)  Mathew J (Design)`.
- **Journey figure:** V2 systems → V3 systems over time; name hardware **only when the slide is about that hardware**.
- **Phase timeline:** Legacy maintenance → Active transition → Next-gen standard (indicative dates called out).
- **Split prose vs figure:** cost-of-parallel argument as short prose + bottom line, then a **second** slide of big metrics (`2x`, `1.5–2x`) — do not cram both.
- **Data-informed composition:** large % breakdown (machine mix) with one insight callout (~90%+ core).
- **Named unsupported hardware** as a clear register (products named → isometrics OK).
- **Team allocation matrix** as the figure when the sentence is about ring-fenced capacity.
- **Architecture / isolation test:** Element under test + API simulation bridge — diagram, not bullets.
